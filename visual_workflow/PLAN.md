# n8n + Dify PoC 計画

目的: 既存システムを維持したまま、新規開発で視覚的な工程構築と実行状況の確認を行う。

## 完了条件と検証
- 固定バージョンの n8n と Dify を WSL の専用 Compose プロジェクトで起動する。
- モデル課金なしの Dify Code ワークフローを n8n から実行し、project-a / project-b の入力を識別する。
- PoC 専用の job API で job ID、状態、結果、エラーを確認する。既存の制作処理は実行しない。
- manifest 検査（`policy.py`）を用意し、change 専用の固定テストから呼ぶ。
- 秘密情報と DB は専用領域に保存し、外部 API キーや既存 workspace をマウントしない。

## 実行境界
PoC は模擬結果を返す。既存システムへの接続、モデル生成、投稿、通知、課金は範囲外。サービスは loopback のみ。自動起動や定期実行は設定しない。
